# Helping a team adopt schema first APIs

[Story selector](../story-bank.md) · [Culture framing](../culture-framing.md) · [Gaps](../gaps.md)

**Use for:** Influence without authority, migration friction and helping another team. A compact episode from S01, not a separate project.

**Research questions:** Q05, Q13; partial support for Q15. **State:** Draft ready for rehearsal. No independent rehearsal recorded.

## Opening

> I addressed a team’s migration cost by implementing its first endpoints and handing over a pattern it used to complete the rest.

## Answer structure

1. **Concern:** The team faced extra adoption work and difficulty synchronizing schemas with the main API.
2. **Response:** Connected schemas to the possibility of contract testing and agreed on practical migration help.
3. **Action:** Personally implemented the first batch of endpoints.
4. **Result:** The team implemented the remaining endpoints.

## Frame for the question

For influence, emphasize understanding their cost and changing the adoption approach. For helping colleagues, emphasize the implemented starting point and completed handover.

**Culture connection:** Selflessness is supported by doing work that helped the other team succeed. This is stronger evidence than saying you persuaded them that your solution was right. See the [memo-based framing guide](../culture-framing.md) for the source and interpretation.

## Spoken draft

> One team was concerned about the extra work involved in adopting schema-first development. They had a problem keeping their schemas synchronized with the main API, so we discussed how schemas on both sides would enable contract testing to improve that integration.
>
> To help with the upfront work, we agreed that I would implement the first batch of endpoints to establish the pattern, and they would take over the rest. I implemented that initial set, and the team then completed the remaining endpoints.

## Keep the claims precise

- Contract testing was an intended benefit, not a confirmed delivery.
- Do not treat adoption concerns as an established technical disagreement, or claim this proves inclusion across backgrounds.

## Follow-up preparation

- What did you learn about making adoption easier? Optional: how much ongoing support was needed?
